# Баг-репорт REDSMS

Трекер баг-репортов в один HTML-файл. Сборка не нужна, зависимостей нет.

## Возможности

- Форма по шаблону баг-репорта: заголовок, окружение, шаги, ожидаемый и фактический результат, серьёзность, приоритет, воспроизводимость, обходной путь.
- Подсказка похожих багов, пока вы пишете заголовок, — чтобы не заводить дубликаты.
- Статусы: Новый → В работе → Исправлен → Закрыт / Отклонён.
- Фильтры по статусу и серьёзности, поиск по тексту.
- Вложения: скриншоты, видео, логи.
- Выгрузка бага в PDF и Markdown (.md) и копирование текста в буфер обмена.
- Создание задачи в Яндекс Трекере: в карточке бага укажите ключ очереди. Откроется форма новой задачи с заполненными заголовком и описанием.

## Запуск

Откройте `index.html` в браузере. Так он работает сразу, но удобнее запустить простой локальный сервер:

```bash
python3 -m http.server 8000
```

Затем откройте http://localhost:8000.

### На сервере или хостинге (Docker)

В репозитории есть `Dockerfile`. Сервер слушает `0.0.0.0` и порт из переменной `PORT`, по умолчанию 8501.

```bash
docker build -t bag-report .
docker run -p 8501:8501 bag-report
```

Если хостинг запускает без Docker, укажите команду запуска (порт — тот же, что в настройке «Порт приложения»):

```bash
python -m http.server 8501 --bind 0.0.0.0
```

Нужен интернет: с внешних CDN подгружаются шрифты Geist и, при выгрузке в PDF, библиотеки html2canvas и jsPDF.

## Где хранятся данные

| Где открыт | Хранилище |
|---|---|
| Как артефакт на claude.ai | Общая база артефакта: баги видят все, кому открыт доступ |
| Локально (файл или свой сервер) | `localStorage` этого браузера, ключ `redsms-bugs` |

В локальном режиме:

- баги видны только в том браузере, где их завели, и пропадут при очистке данных сайта;
- вложения хранятся внутри бага, не больше 2 МБ на файл, а всё хранилище браузера — около 5 МБ;
- чтобы перенести баг в другое место, выгрузите его в .md или PDF.

Для общей командной базы вне claude.ai нужен бэкенд. Замените функцию `localBackend()` в `index.html` адаптером к вашему API: он должен реализовать те же методы `collection().orderBy().onSnapshot()`, `doc().set/update/delete()`.
